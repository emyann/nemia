title: The model
description: What each layer stores, entity by entity, and the one id that links the two.
---

Each layer has its own model: what it stores on disk, what each record holds, and which id names it. The runtime stores tasks, their
attempts, and their sessions. The orchestrator stores runs, their steps, each step's tries and rounds, and around them the inbox, the
factories, the places, the agents, and the feed.

## Linked by id alone

Neither model holds the other's entities. When the orchestrator needs the runtime's work, it keeps the id the runtime gave it: a try
records the `TaskId` of the task it ran as, and nothing more. The orchestrator declares that id as the runtime's without importing
the runtime (`packages/agent-orchestrator/src/record/record.model.ts`), so its diagram shows the runtime's task as a box known only by
its id. To find out what that task did, the orchestrator asks the runtime, through its one client.
