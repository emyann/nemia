This guide takes you from one line in a terminal to your first change landed in your repository, on your own laptop. The board guides
you through four milestones: a harness, a first factory, a first volume, and a first card. Each milestone reflects what Nemia has
right now (a harness activated and signed in, a factory created, a trusted volume, a run landed). So if you complete one in a
terminal, the board shows it as done. You can skip any page.

## Install

```bash
curl -fsSL https://github.com/emyann/nemia/releases/latest/download/install.sh | sh
```

Nemia runs on macOS (Apple silicon or Intel), Linux (x64 or arm64), and Windows in a WSL terminal. On a laptop, the installer asks no
questions. It installs the release, runs Nemia locally, opens the welcome page in your browser, and prints a link to it at
`http://localhost:8787/welcome`. The link signs that browser in to the board. It works once, within ten minutes. If no browser opens,
open the link yourself. Later, run `nemia open` to open the board, signed in, at any time. [Install](/install/) explains what the
installer does, its options, and how to install a server.

## A harness

First, the welcome page asks which harness to activate: Claude Code or Codex. The harness runs Nemia's own agent and every session in
your factories. Nemia doesn't ship one. Click _Activate_, and the page installs the version this release was tested with, then checks
its version. Once the harness is signed in (the page tells you how if it isn't), click _Run the check_. It sends one real turn
through the harness, at a capped cost. Your plan's quota appears once that turn passes.

In a terminal, `nemia doctor fix claude` does the same install. The board's _Setup_ page lists every harness and everything else the
machine needs ([Activate a harness](/install/#activate-a-harness)). Once both checks pass, _Next_ takes you to the next unfinished
milestone.

## A first factory

A factory is where your workflows run, with the agents it hires ([Factories](/factories/)). You can create one in three ways:

- **Talk to Nemia** (recommended). Her chat opens beside the page. Tell her what you build, and she creates the factory with you. The
  page moves on once she has created it.
- **From a template.** Pick a team built into Nemia, such as sdlc, and review its workflows and agents. Name the factory and fill in
  anything the template asks for. sdlc asks for nothing: its settings sit under More parameters, each at its default, and you can
  change them or leave them.
- **From scratch.** Give it a name, and Nemia creates an empty factory, with a short guide to what goes in it: a workflow, an agent,
  and a hire.

A factory can start without a volume: that's the next milestone. In a terminal, `nemia factory apply <name> --template <template>`
creates a factory from a template, and `nemia factory add <name>` creates an empty one.

## A first volume

_Where is the work?_ A factory's runs work in a git repository, called its volume. You can add one in three ways:

- **A folder on this machine.** Type its path, and the page suggests folders as you type. If the folder isn't a git repository yet,
  the page offers `git init`: Nemia turns it into one with a single empty commit, and commits none of your files.
- **A repository by its URL**, on GitHub, GitLab, or any git host. Nemia clones it with this machine's own git credentials
  ([A repository by its URL](/install/#a-repository-by-its-url)).
- **A new repository.** Give it a name, and Nemia creates an empty one in its store.

The volume is added as writable. The page then asks you to trust it: no run starts in a folder until a harness trusts it. Click _Not
now_ to leave the factory waiting, and give that trust later from its Settings.

In a terminal, `nemia factory volume add <factory> <path>:rw` adds a volume and trusts it, and `nemia factory trust <factory>` asks for
trust again.

## A first card

_What first?_ A card describes what you want. A workflow does it in steps, and a gate waits for you before the work lands. Pick one of
three small changes (describe the repository in its README, ignore editor files, fix a typo), or write your own. The card runs in the
factory's quick workflow if it has one. Otherwise, you pick one of the factory's workflows. Above _Start_, the page shows what a small
run costs and how long it takes: the real figures once a run has landed on this machine, an estimate before that.

_Start, gated before it lands_ creates the card, starts its run, and opens the run's page. A hint there shows where the run stands:
the card created, each step's agent at work, then the gate, which waits for you. Read the work, then approve it to land, or send it
back. Once it lands, the hint leads to _You are set_, the last welcome page. It suggests what to do next: raise Nemia's level so she
watches your runs for you, land through your git host if the factory's template supports it, and use Nemia from a terminal or a
coding agent.

[How a run lives](/how-a-run-lives/) follows a run from start to landing.
